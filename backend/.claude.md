# Backend — Python FastAPI

## Stack
- Python 3.12, FastAPI 0.136.3, SQLAlchemy 2.0.50, Alembic 1.18.4
- PostgreSQL (local), Kafka (local Docker), Redis (local Docker)
- Pydantic v2 for all request/response schemas

## Structure rules
- One module per domain folder under `app/modules/`
- Each module has: `router.py`, `service.py`, `schemas.py`, and uses `shared/models/`
- No business logic in routers — routers call services only
- No raw SQL — use SQLAlchemy ORM only
- All DB access through dependency-injected `AsyncSession`

## Database rules
- NEVER write DDL directly — all schema changes via Alembic migration
- Run `alembic revision --autogenerate -m "description"` after any model change
- Run `python ../scripts/check_migrations.py` before committing
- UUID primary keys on all tables — use `gen_random_uuid()`
- All timestamps `TIMESTAMPTZ`, never `TIMESTAMP`

## Auth rules
- Admin/operator routes: validate Keycloak JWT via dependency
- User-facing routes: validate internal session token issued after PIN auth
- Never trust `user_id` from request body — always resolve from authenticated token

## Kafka rules
- Produce events after DB commit, never inside a transaction
- All consumers are idempotent — check `event_ingestion_log` before processing
- Topic names are in `app/config.py` as constants

## Error handling
- Use custom exception classes in `shared/exceptions/`
- All HTTP errors return `{ "error_code": "...", "message": "..." }`
- Never expose stack traces in API responses
