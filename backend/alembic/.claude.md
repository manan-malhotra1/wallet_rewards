# Alembic — Database Migrations

## Rules
- Every migration file must have a one-line docstring describing what it changes
- Naming: `YYYYMMDD_NNNN_description` (e.g. `20260528_0001_create_tenants`)
- Never edit a migration that has already been applied to any environment
- If a previous migration needs fixing, write a new corrective migration
- Run `alembic check` to validate models match current schema — must pass before any deploy

## Generation

```bash
alembic revision --autogenerate -m "your description here"
```

## Apply

```bash
alembic upgrade head
```

## Rollback

```bash
alembic downgrade -1
```

## Current state

```bash
alembic current
```
