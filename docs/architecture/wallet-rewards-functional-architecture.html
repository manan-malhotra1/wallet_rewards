How to read this

The colours are a product boundary, not a code one. A tenant is provisioned as wallet only, rewards only, or both. A wallet-only tenant gets no points pool, no rules engine and no redemption surface; a rewards-only tenant never touches the money core. That is why the blue and gold halves are drawn as separate stacks: each has to stand up without the other. The green foundation exists once and serves whichever halves are switched on.

Purple is the interesting part, and it only exists in a both-mode tenant. Points and money are different kinds of value, so every crossing between them is explicit: a conversion rate that fails closed when it is not configured, a points redemption wallet that receives burned points, and a cashback provider wallet that funds every payout. Nothing converts implicitly and there is no default rate.

One ledger, one choke point. Every movement of value, money or points, is an append-only double entry posted through a single function that holds the row locks, enforces the overdraft floor and the balance ceiling, and dedupes on the idempotency key. Balances are derived by summing entries, never stored and updated. A reversal appends opposite legs; nothing is ever edited in place. That is what lets a points burn and a fiat payout be reasoned about with the same rules.

Money paths fail closed. A service may only run if both a pricing config and a limit config resolve for the acting user. A zero fee or an unlimited cap has to be an explicitly configured row, never an implicit default, so a missing config stops the transaction instead of silently letting value through.

Two different maker-checker flows, deliberately. Config changes (pricing, limits, tax, step-up, conversion rates) go through the config change request pipeline. Money movements (fund, withdraw, adjust) go through money operations with N distinct approvers. Both are green because both halves rely on them, but they guard different things: one guards the rules, the other guards the cash.

Points and money keep separate statements. The transaction history is money only. Points earned and points redeemed live in the rewards history behind the points balance. When a redemption pays out, the fiat leg appears in the money statement because real money arrived, while the points burn appears only on the rewards side. The two are cross-referenced so either leg resolves to the other.
