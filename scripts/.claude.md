# Scripts — Developer Utilities

## `check_migrations.py`
Runs `alembic check` to verify all model changes have a corresponding migration.
Must pass before any commit that touches `shared/models/`.
CI runs this automatically.

```bash
python scripts/check_migrations.py
```

## `seed.py`
Seeds local database with:
- One default tenant (wallet mode, ZAR)
- Admin user and test users with identifiers
- Sample rules (milestone P2P, streak, first-time top-up)
- Sample tiers (Bronze, Silver, Gold)
- Sample badges

```bash
python scripts/seed.py
```

## Running via make

```bash
make seed       # runs seed.py
make check      # runs check_migrations.py
make dev        # starts uvicorn with reload
```

## `load_test.sh` / `load_test_p2p.py`
Single-service P2P load test — sustained-TPS against a running backend. The shell
wrapper picks the backend venv and applies 5-minute / 50-concurrency defaults;
every flag passes through to the Python script (`--help` is the full reference).

```bash
scripts/load_test.sh --duration 60 --concurrency 50 --min-amount 5
```

Setup is idempotent and cached in `--state-file`, so re-runs skip provisioning.
Pass `--min-amount 5`: the seeded `Sasai-ZA` p2p limit sets a R5 per-txn floor and
the script's default of 1 otherwise logs spurious `amount_below_min` failures.

## `load_test_mixed.py`
Consolidated multi-service load test — drives p2p, cashout, airtime, cash_in and
merchant_cashin in one weighted stream and reports per-service TPS + p50/p95/p99.
Reuses the setup helpers in `load_test_p2p.py`, so the maker-checker funding logic
lives in one place.

```bash
backend/.venv/bin/python scripts/load_test_mixed.py --duration 60 --concurrency 50
backend/.venv/bin/python scripts/load_test_mixed.py \
    --weights p2p=50,cashout=20,airtime=20,cash_in=10 --phase setup
```

It provisions what each service requires: a `super_agent -> agent` chain (cash_in
is agent-only and cashout must target an agent), a `head_merchant -> merchant`
chain plus API keys for the HMAC-signed external endpoint, and role grants for
cashout / airtime_recharge (the `load-test-user` role grants p2p only).

Two environment gotchas that make a run misleading rather than failing loudly:
- The seeded `merchant_cashin` limit row caps that service at **1 txn/day per
  merchant** (R25/day). Raise it via the config-requests maker-checker flow or
  that leg 429s on the second call.
- The external API is rate-limited to **60 requests/min per API key**, so
  merchant_cashin is ~1 TPS per key; `--merchant-keys` mints several.

Numbers from `make dev` are a floor, not capacity: that server is a single-process
`uvicorn --reload` and `create_async_engine` sets no `pool_size` (15 connections),
so throughput peaks at low concurrency and degrades as concurrency climbs.
